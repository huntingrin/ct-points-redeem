# 中国电信积分兑换 Skill

打开中国电信移动版积分商城，读取本机积分和当前商品目录，再由用户选择**话费、流量或影音组合**。Agent 负责比较、准备收银台、按本笔授权提交并核对结果；登录和支付短信验证由本人在官方页面完成。

默认只办理**本机、现金补款 0 元、无自动续订、规则明确**的权益。商品、积分价格、面额、有效期和号码资格均以本次官网页面为准，不预置静态商品表。

## 最短路径：2 次短信

| 步骤 | 动作 | 短信 |
|---|---|---|
| 1 | 用 iPhone UA + 390×844 移动视口打开商城 | — |
| 2 | 登录商城 SSO（`m.telefen.com`） | 第 1 次 |
| 3 | 读积分、选商品、核对规则 | — |
| 4 | 点一次「兑换」进入收银台 | — |
| 5 | 核对积分/现金，点「确认支付」 | 第 2 次 |
| 6 | 查积分余额、订单状态、到账 | — |

**不要先登录星级中心，也不要登录 PC 账号 `login.189.cn`。** 两条路都会多一次短信，且不会让商城免登录。

## 关键修复：移动 UA

移动版话费页在**桌面 UA** 下创建订单后，收银台 `cashier.telefen.com` 会 302 回 `jf.189.cn/pchome`，看起来像“登录失效/跳回首页”。正确做法是**打开页面前**就设置移动端环境：

```js
await page.cdp("Emulation.setUserAgentOverride", {
  userAgent: "Mozilla/5.0 (iPhone; CPU iPhone OS 17_0 like Mac OS X) AppleWebKit/605.1.15 (KHTML, like Gecko) Version/17.0 Mobile/15E148 Safari/604.1",
  acceptLanguage: "zh-CN,zh;q=0.9", platform: "iPhone",
});
await page.cdp("Emulation.setDeviceMetricsOverride", {
  width: 390, height: 844, deviceScaleFactor: 3, mobile: true,
});
```

如果已经跳回 PC 首页：**停止点兑换**，切移动 UA，查订单；只继续支付一笔，其余关闭。重复点击会生成多笔待支付订单。

## 安装

```sh
git clone https://github.com/huntingrin/ct-points-redeem.git
```

将整个仓库作为 `ct-points-redeem` 文件夹放入宿主的技能目录，例如 Codex 的 `~/.codex/skills/`。也可让具备浏览器能力的 Agent 直接读取 [SKILL.md](SKILL.md)。

先查询可说：

> 用 $ct-points-redeem 登录电信积分商城，查我的积分，列出可兑的话费和流量，先不兑换。

用户选定完整商品、数量及费用后，Agent 按授权继续。验证码直接填在官方页面，不发到聊天。验证后先判断是否已付款或生成订单，再决定是否继续，避免重复扣分。

## 运行要求

- 宿主具备浏览器导航、读取页面、填写和点击能力，并遵循其页面所有权、后台操作及人工交接规则。
- 本人在中国电信官方页面完成登录和支付验证；复用有效会话，无需导出 Cookie。
- 可选的本地提交保护脚本使用 Python 3 标准库，文件锁依赖 macOS/Linux 的 `fcntl`。没有相应执行能力时，由 Agent 按同样规则维护私有断点。

脚本只记录计划、提交断点和核对结果，不控制浏览器、不读取短信、不执行兑换。运行状态保存在仓库外的私有任务目录。用法见 [状态脚本说明](skills/ct-points-redeem/references/transaction-state.md)。
